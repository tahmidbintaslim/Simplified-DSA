# বাইনারি সার্চ

বাইনারি সার্চ সাজানো তালিকায় একটা মান খুঁজে বের করে এভাবে: মাঝখানের মানটা দেখো, যে অর্ধেকে মানটা থাকতেই পারে না সেটা বাদ দাও, তারপর আবার একই কাজ। দশ লাখ মানের মধ্যে যেকোনোটা এভাবে খুঁজে পাওয়া যায় মোটামুটি 20টি চেকে। তবে সেসবের আগে চলো একটা খেলা খেলি।

> **উপমা:** কাগজের অভিধানে শব্দ খোঁজার কথা ভাবো। তুমি মাঝামাঝি একটা পাতা খোলো, দেখো তোমার শব্দটা আরও পরে, আর পুরো প্রথম অর্ধেকটা ভুলে যাও। তারপর বাকিটা আবার ভাগ করো। পাতার পর পাতা কখনো পড়ো না।

## মূল ধারণা {#the-core-idea}

ওই খেলাটাই বাইনারি সার্চ। কোডে লিখতে হলে তালিকার যে অংশে লক্ষ্য-মানটা (target) এখনো থাকতে পারে, সেটার হিসাব রাখতে হয় দুটি অবস্থান দিয়ে:

- `lo`: এখনো বিবেচনায় থাকা প্রথম ইনডেক্স,
- `hi`: এখনো বিবেচনায় থাকা শেষ ইনডেক্স,
- `mid`: এ দুটির ঠিক মাঝের ইনডেক্স, যেটা তুমি চেক করো।

> **মূল ধারণা:** এটা কাজ করে শুধু **সাজানো** ডেটায়। সাজানো আছে বলেই বোঝা যায় কোন অর্ধেকটা বাদ দেওয়া যাবে। এলোমেলো তালিকায় একটা কার্ড উল্টালে তার পাশের কার্ডগুলো সম্পর্কে কিছুই জানা যায় না।

## এত দ্রুত কেন {#why-it-is-so-fast}

| 16 | 16 | 5 |
| 1,000 | 1,000 | 10 |

## কোড {#the-code}

```python
def binary_search(values, target):
    lo, hi = 0, len(values) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if values[mid] == target:
            return mid
        if values[mid] < target:
            lo = mid + 1   # বাম অর্ধেক বাদ
        else:
            hi = mid - 1   # ডান অর্ধেক বাদ
    return -1              # lo পেরিয়ে গেছে hi-কে: পাওয়া যায়নি
```

মাত্র সাত লাইন, আর তার দুটি লাইন ভেঙে যাওয়ার জন্য বিখ্যাত। বাইনারি সার্চ বোঝানো সহজ, কিন্তু ভুল করাও অবাক করার মতো সহজ: বাগগুলো লুকিয়ে থাকে কিনারার ছোট ছোট খুঁটিনাটিতে। তাই চলো ইচ্ছে করেই এটা ভাঙি। একটা সুইচ উল্টাও, একটা লক্ষ্য-মান বেছে নাও, আর দেখো কী হয়।

প্রথম সুইচটা চালু রেখে `30` খোঁজো: লুপ থেমে যায় ঠিক যখন `30`-ই একমাত্র বাকি মান, সেটাকে একবারও না দেখে। তারপর ওই সুইচ বন্ধ করো, দ্বিতীয়টা চালু করো, আর `10` খোঁজো: `hi` এমন একটা মানের ওপর আটকে যায় যেটা বেশি বড়, আর আর কখনো নড়ে না। দুটি বাগই বেশিরভাগ টেস্ট পাস করে যায়, আর ঠিক এজন্যই এরা ইন্টারভিউ পর্যন্ত টিকে থাকে।

> **সাবধান:** `lo <= hi` লেখো (`<` নয়), নইলে শেষ প্রার্থীটা বাদ পড়ে যায়। `mid + 1` আর `mid - 1` লেখো (শুধু `mid` নয়), নইলে পরিসর ছোট হওয়া থেমে যেতে পারে আর লুপ চিরকাল চলবে।

```deep-dive
title: আরও গভীরে: কিছু কোডে কেন `lo + (hi - lo) // 2` লেখা হয়
Python-এ পূর্ণসংখ্যা যত দরকার তত বড় হতে পারে, তাই `(lo + hi) // 2` সবসময়ই ঠিক আছে। কিন্তু যেসব ভাষায় পূর্ণসংখ্যার মাপ নির্দিষ্ট (Java, C, C++), সেখানে তালিকায় প্রায় একশো কোটির বেশি মান থাকলে `lo + hi` একটা `int`-এ ধরা সবচেয়ে বড় সংখ্যাকেও ছাড়িয়ে যেতে পারে। যোগফলটা ঘুরে গিয়ে ঋণাত্মক সংখ্যা হয়ে যায় (overflow), আর `mid` আজেবাজে জায়গা দেখায়।

`lo + (hi - lo) // 2` দুটি বড় সংখ্যা যোগ না করেই একই মাঝখান দেয়। ঠিক এই বাগটা Java-র নিজস্ব লাইব্রেরির বাইনারি সার্চে প্রায় এক দশক ধরে বসে ছিল, কেউ খেয়াল করার আগে।
```

> **কখন ব্যবহার করবে:** ডেটা সাজানো (বা একবার সাজিয়ে নিয়ে বহুবার খোঁজা হবে), কিংবা সমস্যাটা জানতে চায় "প্রথম কোন অবস্থানে কোনো শর্ত সত্য হয়"। বাইনারি সার্চ উত্তরের ওপরও চলে: "সবচেয়ে কম কোন গতিতে চললে সময়মতো শেষ হবে?"

## মনে রাখো {#what-to-remember}

- সাজানো ডেটা আর "অর্ধেক বাদ দাও" মিলে হয় `O(log n)`।
- `lo` আর `hi`-এর হিসাব সাবধানে রাখো; `lo` যখন `hi`-কে পেরিয়ে যায়, থামো।
- আগে সর্ট করতে হলে তার খরচ `O(n log n)`, তাই এটা লাভজনক যখন বহুবার খুঁজবে।

## অনুশীলনী {#practice-prompt}

`[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]`-এ `23` খোঁজার প্রতিটি ধাপে `lo`, `mid` আর `hi` লেখো। তারপর একই কাজ করো `60`-এর জন্য, যা তালিকায় নেই।

```answer
ইনডেক্স 0 থেকে 9 পর্যন্ত।

`23` খোঁজা:

1. `lo=0`, `hi=9`, `mid=4`: 16, যা 23-এর চেয়ে ছোট, তাই `lo=5`।
2. `lo=5`, `hi=9`, `mid=7`: 56, যা 23-এর চেয়ে বড়, তাই `hi=6`।
3. `lo=5`, `hi=6`, `mid=5`: 23। ইনডেক্স 5-এ পাওয়া গেল, 3টি চেকে।

`60` খোঁজা:

1. `lo=0`, `hi=9`, `mid=4`: 16 ছোট, তাই `lo=5`।
2. `lo=5`, `hi=9`, `mid=7`: 56 ছোট, তাই `lo=8`।
3. `lo=8`, `hi=9`, `mid=8`: 72 বড়, তাই `hi=7`।
4. এখন `lo` (8) `hi` (7)-এর চেয়ে বড়: পাওয়া যায়নি, 3টি চেকের পর।
```
